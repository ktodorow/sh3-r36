## Existing Linux runtime avoids Switch emulation

This project is static recompilation of **original PC executable**, with custom Windows API replacements and D3D8-to-OpenGL renderer. Build host patches and analyzes original x86 executable, then emits C; target compiler turns that generated C into native host code. Existing targets demonstrate Switch ARM64 and Linux x86-64 separately. Linux ARM64 combines those foundations but remains untested here. Native AArch64 ELF is correct starting point; Switch NRO, devkitPro/libnx, Wine, Box64 and Switch emulator add no necessary capability to selected route. [Architecture](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/README.md#L16), [generation pipeline](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/tools/regen.sh#L1).

Root build combines generated code with `src/runtime`, `src/win32`, `src/d3d8` and `src/game`; Linux links SDL2, pthread and libm. Switch-specific libraries and packaging sit behind `NINTENDO_SWITCH`. Preserve `-fwrapv` and `-fno-strict-aliasing`, which support translated guest semantics. Vendored Xbox runtime/backend descriptions do not describe active game renderer: root build uses custom `src/d3d8`, so generic vendored Xbox graphics tests cannot certify it. [Root CMake](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/CMakeLists.txt#L8).

Standard R36S specification is **RK3326, quad core Cortex-A35, Mali-G31, 1 GB RAM, 640×480 screen and two sticks**. Rockchip advertises GLES3.2/Vulkan1.0 silicon support. Installed driver determines usable interfaces: owner’s cached October logs show proprietary ARM Mali-G31 GLES3.2, while current Mesa Panfrost documentation lists G31 desktop GL3.1/GLES3.1. Neither hardware branding nor another firmware’s Mesa capabilities prove current device configuration. [PortMaster supported hardware](https://portmaster.games/installation/supported-handhelds/), [Rockchip RK3326 announcement](https://www.rock-chips.com/a/en/News/Press_Releases/2018/0413/898.html), [Panfrost feature table](https://docs.mesa3d.org/drivers/panfrost.html).

## GLES3 preserves renderer structure but requires real adaptation

Context creation tries desktop core **4.6, 4.5, then 4.3**, rejecting older contexts. Generated shaders declare `#version 430 core`; mandatory-symbol loader also demands desktop symbols regardless of active use. Launcher opens same context before gameplay. Changing version request alone therefore cannot establish compatibility. [Context creation](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/d3d8/d3d8.c#L130), [loader](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/d3d8/gl.c#L8), [symbol list](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/d3d8/gl.h#L7), [launcher](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/d3d8/launcher.c#L430).

Source census found ordinary vertex/fragment shaders, uniforms, attributes, varyings and 2D/cube samplers; no active compute, geometry/tessellation, SSBO, UBO, texture-array or indirect-draw dependency. Translator supports 16 attributes and 96 vec4 constants; wrapper declares 10 vec4 varyings plus two floats and eight fragment samplers. **Desktop version request overstates underlying feature complexity**, but static census does not enumerate every shader/state combination exercised later in campaign. GLES3 retains more existing structure than GLES2 downgrade. [Shader translation](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/d3d8/d3d8_shader.c#L218), [shader wrappers](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/d3d8/d3d8_shader.c#L516).

## Full-game scope adds CPU, memory and video risks

Translated C still implements x86 registers, floating-point state, indirect calls and guest memory semantics. Existing 64-bit-host abstraction preserves 32-bit guest addresses as offsets into pointer-sized host arena. Linux reserves **4 GiB virtual address space**, committing selected pages; this is **not 4 GiB physical RAM requirement**. Guest heap spans `0x10000000` to below `0xF0000000`, rounds allocations to powers of two, commits 8 MiB increments and keeps 64 MiB freed-block quarantine. Quarantine compensates observed lifetime bugs, so shrinking it blindly risks correctness. [Guest addressing](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/runtime/rt.h#L8), [Linux arena](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/runtime/host.c#L218), [allocator](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/runtime/rt_core.c#L116), [translated CPU helpers](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/third_party/xboxrecomp/templates/runtime/recomp_types.h#L44).

Physical-memory fit is unknown. Original guest texture copies, conversion buffers and GPU allocations can coexist. RGBA8 expansion uses eight times DXT1 or four times DXT3/5 compressed storage for corresponding GPU image, before temporary buffers and retained source copies. These are format arithmetic, not measured SH3 totals. Reducing 640×480 to 320×240 quarters pixel count and reduces render-target storage; it does not proportionally shrink textures, guest heap, generated code or audio. CPU-limited gameplay will not become 30 FPS merely through lower resolution. [Texture storage and uploads](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/d3d8/d3d8_res.c#L170).

Audio adds software mixing and guest scheduling risk. Existing DirectSound bridge opens SDL stereo float output at 44.1 kHz with 1024-sample buffer. Linux uses pthreads and signal/pipe suspension; its `host_use_single_core` is no-op, while Switch path documents CRI race workaround. If race appears, implement/test actual Linux guest-thread policy; whole-process affinity also constrains rendering and decode. **30 FPS presentation must preserve original movement, combat, animation and audio timing**. Monotonic clocks and vsync exist, but complete game-timing model was not traced. [Audio bridge](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/win32/dsound.c#L444), [thread handling](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/runtime/host.c#L151), [Switch race note](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/runtime/host.c#L38), [timers](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/win32/kernel32.c#L456).

**Original FMVs require new integration.** Upstream skips `data/movie/*.000`; `CoCreateInstance` always returns class-not-registered. Actual codec/container remains unknown because original media was unavailable. Inherited `Open.bik` comment does not prove SH3 videos use Bink. Inventory original files with file-signature and ffprobe checks, then trace game-used movie calls. Candidate implementation uses narrow game-call/DirectShow bridge into libavformat/libavcodec, GLES frame upload and SDL audio clock, conditional on real media support and measured decode speed. VPU acceleration is separate firmware-dependent work, not established shortcut. [Known FMV omission](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/README.md#L82), [missing object creation](https://github.com/cutarev/sh3-nx/blob/ff483a6f95b94a4f7924f6fbe4cb47169f2adb98/src/win32/user32.c#L200), [FFprobe](https://ffmpeg.org/ffprobe.html), [libavcodec](https://ffmpeg.org/libavcodec.html).
